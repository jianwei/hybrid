# UI 定制规则

适用于本项目所有运行平台的界面、组件样式、主题和布局任务；具体组件库及平台能力遵循对应平台规则。

## 定制优先级

- 先检查现有组件和组件库公开 API。按满足需求所需的最小改动选择：组件属性与主题配置 → 平台支持的主题变量或样式令牌 → 局部样式覆盖 → 插槽、组合与包装 → 自定义或替换组件。
- 使用主题变量、CSS 选择器或插槽前，确认目标平台和已安装版本支持该能力；React Native 等平台采用其实际支持的样式机制。
- 自定义或替换组件时，说明现有能力的具体缺口，并保留所需的交互、无障碍和平台适配行为。
- 优先使用公开扩展接口；复制组件库源码后，记录来源与版本，并在依赖升级时检查该组件是否需要同步。

## CSS 尺寸与单位

- 本规则适用于仓库维护的业务 CSS、Sass 及组件内联样式，覆盖所有运行平台；`node_modules` 等第三方源码、`dist` 等构建产物和工具生成文件不在强制改写范围内。
- 样式源码的长度和尺寸统一使用 `px`，禁止 `rem`、`em`、`vw`、`vh`、`fr` 等其他长度或相对单位。H5 仍在构建阶段把业务源码的 `px` 转为 `rem`，不得把产物单位反写到源码。
- 所有声明值禁止百分比，包括布局、变换、颜色函数和自定义属性中的百分比；例如 `width: 80%`、`translateX(50%)` 均不允许。关键帧的 `0%`、`100%` 是进度选择器，不属于声明尺寸，可以保留。
- 零值可以省略单位；`line-height`、`flex`、`opacity`、`font-weight` 等本身允许无单位数值的属性继续使用无单位值，`auto`、`inherit`、`normal` 等 CSS 关键字也可以保留。
- 时间、角度、频率和分辨率不是长度，按 CSS 语义使用 `ms`、`s`、`deg`、`grad`、`rad`、`turn`、`Hz`、`kHz`、`dpi`、`dpcm`、`dppx` 或 `x`，不能改写为 `px`。
- 大写 `PX` 仅用于明确跳过 Taro `pxtransform` 的固定像素值，并就近说明原因；普通业务尺寸使用小写 `px`。
- 需要响应式布局时使用 Flex、Grid、内容自适应关键字和以 `px` 为单位的媒体查询，不用百分比或视口单位规避本规则。

`apps/taro` 的 Stylelint 会检查自有样式文件中的声明单位；组件内联样式按同一规则人工评审。新增其他样式源码目录时，将其加入对应项目的样式检查入口。

## 验证

- 核验受影响页面的布局、交互和样式；涉及暗色模式、响应式布局或多语言时，覆盖本次改动涉及的状态。
- 修改共享组件时，明确受影响的平台，并按平台规则验证；以目标平台实际结果说明验证范围。
- 执行项目样式检查，确认百分比和非 `px` 长度单位会失败，合法的 `px`、必要的固定 `PX`、无单位值以及非长度物理单位可以通过；同时检索组件内联样式，补足 Stylelint 无法覆盖的部分。
