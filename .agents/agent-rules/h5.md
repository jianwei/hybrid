# H5 规则

平台文档：[MDN Web 文档](https://developer.mozilla.org/zh-CN/docs/Web?from=taro)。

## 开发

- 需要浏览器 DOM 或 Web API 时，将相关逻辑限定在 H5 平台分支或 H5 专属模块，并核对其他目标平台的编译结果。
- H5 构建与路由配置在 `apps/taro/config/index.ts` 的 `h5` 节点；开发、生产差异分别在 `config/dev.ts`、`config/prod.ts`。页面 HTML 模板位于 `src/index.html`。
- 当前 H5 使用 browser History 路由和根路径资源地址。新增或修改路由时，核对直接访问、刷新子页面能回退到 `index.html`，且静态资源路径仍按文件路径响应。

## 尺寸与单位

- H5 页面以 375px 视口为设计基准，不固定页面宽度，也不把内容容器强制限制为 375px；页面仍跟随实际移动端视口响应。
- 375px 视口的根字号为 16px，其他视口按 `16 × 视口宽度 ÷ 375` 等比计算。Taro 运行时负责设置根字号，`app.scss` 中的 16px 仅作为脚本执行前或不可用时的回退值。
- 应用页面和组件按 375px 设计稿使用 `px` 编写尺寸，由 H5 的 `pxtransform` 统一输出为 `rem`。例如源码 `16px` 输出 `1rem`，在 375px 视口呈现为 16px；不要再手工除以 16 或叠加另一套根字号脚本。
- Taroify 1.0.6 的内置样式采用 750px 设计基准并通过 `$hd: 2` 表达移动端尺寸。构建配置按样式来源保留其 750px 换算，业务侧不要再次缩小组件库样式；业务自定义样式仍按 375px 规则编写。
- 以上换算仅放在 `h5.postcss.pxtransform` 中；共享的 `designWidth` 与其他端换算不得随 H5 设计基准一起修改。

## UI 组件

- 新增或修改 H5 界面时，尽可能使用 Taroify 的现有组件；优先通过组件属性、组合与主题变量满足需求。现有组件无法满足时，再采用自定义实现，并说明缺口。
- 选用或调整 Taroify 组件前，实时读取[官方完整文档](https://taroify.com/llms-full.txt)中的相关章节，核对 API、样式和交互用法；以项目实际安装版本确认可用能力。文档仅在线查阅，不下载或维护本地副本。
- 沿用项目已配置的组件与样式按需引入方式。共享页面使用 Taroify 时，将其限定在 H5 专属模块或平台分支，并验证其他目标平台仍可编译。

## 验证

- 在仓库根目录运行 `pnpm build:h5`。页面或样式变更还需在目标移动端视口检查实际渲染与交互。
- 尺寸规则变更至少检查 375px 视口根字号为 16px、业务样式的 `px` 已输出为 `rem`，并在窄于和宽于 375px 的移动端视口确认等比响应；如页面使用 Taroify，再检查组件尺寸没有二次放大。
- 涉及浏览器兼容性时，以 `apps/taro/package.json` 的 `browserslist` 和真实目标浏览器为准；构建通过不等于设备兼容。
