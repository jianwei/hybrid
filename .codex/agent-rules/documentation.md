# 文档维护规则

适用于项目说明、开发指南、API 文档、迁移说明和文档站内容。

## 内容与变更

- 写文档前读取相关源码、公开类型、配置、示例和已有文档；涉及运行结果时采用实际验证证据，明确尚未验证的范围。
- API、配置、命令或用户可见行为变化时，检查并更新对应文档。没有文档影响时说明判断依据。
- 优先更新已有页面；新工作流或概念需要独立说明时再新增页面。按主题或工作流组织内容，示例保持简洁、可运行且符合项目实际版本。
- 沿用现有文档语言、目录、格式和包管理器。普通文档维护保持现有载体；新建文档站或迁移框架按用户授权范围执行。

## 摘要与验证

- 对已有摘要，页面修改后检查是否仍准确；仅批量补全缺失摘要时，保留有效的已有内容。摘要用与正文一致的语言和具体的纯文本描述。
- `title`、`description` frontmatter 用于采用该约定的文档站页面；普通 README、规则文件和研究记录沿用各自格式。
- 检查修改涉及的链接、示例、导航、资源和元数据。文档站任务执行其实际构建；构建无法执行时说明原因与已完成的检查，不将静态检查表述为构建通过。
- 文档站产物与缓存目录遵循[项目输出约定](../PLATFORM_RULES.md)，新增软件要求同步到[软件要求](../../docs/requirements.md)。

这些原则提炼自 [Rspress 文档生成 skill](../../.agents/skills/rspress-docs-generator/SKILL.md)、[最佳实践 skill](../../.agents/skills/rspress-best-practices/SKILL.md)与[摘要生成 skill](../../.agents/skills/rspress-description-generator/SKILL.md)；Rspress 专属操作按 [Rspress 规则](rspress.md) 执行。
